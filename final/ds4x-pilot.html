同一批任务的四次尝试

每题成功 c 次时，pass¹ = c/4，pass⁴ 仅在 c = 4 时取 1，再对题目平均。例如一题三次成功、一次失败，对两个指标分别贡献 0.75 和 0。

十题检查点与反证

004 · 转人工也可能得零分

保留一条成功对话和工具调用，仅把转人工原因从账户归属争议改成 other。官方 ACTION 得分从 1 降为 0。该题只比较 reason，summary 的措辞不影响这项匹配。

001 · 口头建议无法代替申请

保留原有对话，移除用户提交信用卡申请的调用及回执。从同一初态重放，官方 DB 得分从 1 降为 0。

098 · 推荐对了也可能失败

trial 0 两组都提交了 Blue Account，BM25 的三个参考动作也全部匹配。仅移除额外的账户查询工具解锁与后续调用后，DB 从 0 变 1。这个反事实定位到两步的合并效果。
102 的两种零分值得区分。 在 trial 0 中，BM25 的最终数据库匹配，裁判认为客服没有给出指定企业推荐；Gold 的推荐通过裁判，最终数据库却不匹配。两组同得 0，改进方向分别落在政策解释和业务执行。

  • 逐题比对官方公开 Terminal 轨迹内嵌的 97 个任务。用官方 Task 类型归一化后，用户情境、初始状态、评分条件、所需文档和用户工具五类字段全部一致。Gold 的每个引用均能在对应提示中找到完整正文。
  • 把任务私有脚本与裁判参数改为标记字符串，再清空文档标签。两组政策提示均未出现标记。BM25 提示不变，Gold 提示随文档标签改变。公开运行器在本地分配角色，普通 LLMAgent 工厂只接收政策、代理工具及模型配置。两组代理工具集合仅相差 KB_search，实测检索一次返回十个文档 ID。轨迹中的 Ref 由报告端离线读取。
  • 十题的 80 条轨迹已从初态离线重放；逐项动作、DB 检查和最终成绩均与原记录一致。102 的八条自然语言判定沿用已有裁判回执。全库有 87 题以 DB 评分、9 题以 ACTION 评分、1 题使用 DB 和自然语言断言（102）。DB 比较包含副作用的最终状态，逐项动作命中可单独查看。
